── Root-Cause Summary ───────────────────────────────────────────────
The gradient peak at the LEFT jamb sits at diff-index (left_integer_px - 1).
The gradient peak at the RIGHT jamb sits at diff-index right_integer_px.
The current code measures width_px = right_idx - left_idx, which equals
  (right_integer_px) - (left_integer_px - 1) = true_px_span + 1 pixel
when both boundaries happen to land exactly on integers.
For boundaries that do NOT land on integers the int(round()) quantisation
adds an additional rounding residual of (rnd_right - rnd_left) pixels.
Total bias per opening = (1 + rnd_right - rnd_left) * m_per_px
  which ranges from +0.75 cm to +3.60 cm across the 9 openings.

FIX: replace integer-pixel peak indexing with sub-pixel edge localisation:
  - For each gradient peak find the exact sample where the depth profile
    crosses the midpoint between wall depth and void depth (threshold = 1.0 m).
  - Use linear interpolation on consecutive samples: t = (thresh-d[i])/(d[i+1]-d[i])
  - left_edge_continuous  = i + t  (at the rising wall→void transition)
  - right_edge_continuous = i + t  (at the falling void→wall transition)
  - width_m = (right_edge_continuous - left_edge_continuous) * m_per_px
  This eliminates both the +1 pixel offset AND the rounding residual,
  leaving only dToF sensor noise (~4 mm std, expected error < 1 cm).

Predicted post-fix pass rate: 9/9 = 100%
  (sensor noise std = 4 mm; 1.96*4mm = 7.8 mm < 2.0 cm gate)
  Conservative bound: at least 8/9 (89%) even if one opening is unlucky.
